# 刷钱机 v3 研究计划（已执行，结果见 2026-10-15_刷钱机v3_结果.md）

日期：2026-10-15　｜　前提：ML_v2 和随机对照组在服务器上**原样跑满 56 天，不改一行**

## 目标
1. **降低成本**：v2 的预测能力是真的，但大部分利润被手续费、价差和资金费吃掉。v3 要在同样的币池里留下更多利润。
2. **小资金特化版**：你上真钱的启动资金很少，要专门为几百到两千 USDT 设计一个版本。
3. **找"别人没有的信息"**：用更花哨的模型很难再提升了，真正的优势通常来自数据。

## 规则（先定死，避免"试到好看为止"）
- **试验上限 12 次**：加上之前的 47 次，一共 59 次；Deflated Sharpe 按 59 次校正。
- **锁定考试区不动**：只在 2026-04 之前的开发数据上研究。
- **v3 先过门槛 A 才进模拟盘**：通过的话，在模拟盘加第四个账户，从加入那天起单独计时 56 天，和 ML_v2 同一时间段直接比较。
- 每个方向写清楚要验证的假设，没过就记录下来，不改了再试。

## 研究方向（按优先级）

### A. 降成本（同一币池，最便宜、最可能有效）
- [x] **A1 信号平滑**（2 次试验）：对模型分数做指数平滑（半衰期 2 天 / 5 天）后再交给优化器。假设：日间噪声少了，换手下降，净收益上升。
- [x] **A2 资金费进预期收益**（1 次）：把"持有期间预期要付或要收的资金费"直接写进优化目标。v2 在回测里每年付约 4.6% 的资金费。
- [x] **A3 预测 3 天而不是 1 天**（1 次）：LightGBM 和 Kronos 都改成预测 3 天。信号更慢、更稳，换手更低。

### B. 小资金特化版
- [x] **B1 集中持仓**（2 次）：只做信号最强的多空各 5 个 / 8 个币，按最小下单量取整，在 500 / 1000 / 2000 USDT 三种资金规模下评估。
- [x] **B2 扩大币池**（2 次）：从日均成交额 ≥ 2000 万美元（今天 34 个币）放宽到 ≥ 200 万美元（今天 125 个币）。小资金几乎没有冲击成本，文献也显示这类币的超额收益更大；但价差更宽，成本模型用偏保守的那条曲线。

### C. 新信息（最可能产生真正的优势）
- [x] **C1 跨交易所差异**（2 次）：Binance、Bybit 和 OKX 之间的资金费差、价格差。公开接口有历史数据，同一个币在不同交易所的资金费差往往会回归。
- [x] **C2 事件**（1 次，需要先搭数据）：上币、下币、代币解锁、交易所公告。用 LLM 把公告抽取成结构化事件（这是 LLM 真正擅长的），作为特征。

### D. 模型本身
- [x] **D1 微调 Kronos**（1 次）：用你 Mac 的显卡，只在训练期数据上微调，看看能否超过直接拿来用的效果。

## 上真钱试点（等前向测试过关后再定）
- **资金**：500–2000 USDT。目的是验证真实成交、滑点、接口问题，**不是为了赚钱**。
- **仓位**：按估计 Sharpe 的半凯利上限，宁小勿大。
- **硬止损**：试点资金亏 30% 就停，复盘后再决定。

## 试验的精确定义（2026-10-15 开跑前登记，之后不改）

**共同设定**
- 评估区间：干净窗口 2024-07-01 → 2026-03-28（Kronos 训练数据之后、锁定考试区之前），和 v2 以及随机对照组的分布完全相同。
- 成本模型、风控约束都和 v2 相同。
- 结果全部记入 `runs/ml/trials.sqlite`，类别名 `dev-v3`。
- **比较基准**：v2 = LightGBM(1 天) + Kronos(1 天)，κ=3，净 Sharpe 1.45。
