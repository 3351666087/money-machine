# 刷钱机 1.0 可行性调研：虚拟钱包 + 实时真实行情

日期：2026-10-08　｜　范围：只做调研，不写代码

---

## 一句话结论

**模拟盘本身在技术上完全可行，成本低，1–2 周就能搭出 MVP。但"刷钱"这件事目前没有证据。** 手上三个项目里，没有一个给出过"样本外 + 扣除真实成本后仍然正收益"的记录。所以 1.0 的正确定位是**验证器**：用不花真钱的方式，把"这些东西到底能不能赚钱"测出来。

## 1. 三个项目实际是什么

| | PA_Agent | AlphaMaster | Detect S/R |
|---|---|---|---|
| 本质 | 大模型两阶段分析：市场诊断 → 下单决策（入场价/止损/止盈） | 强化学习自动搜索因子公式，`仓位 = tanh(因子)` | 从 K 线识别支撑/阻力位，并给出触及概率和守住概率 |
| 形态 | PyQt6 桌面 GUI。核心编排器可以脱离界面运行（仓库里有现成的无头 smoke 脚本） | FastAPI 网页端：训练 / 回测 / 实时信号 | Flask 网页端 + 回测框架 |
| 能否下单 | **不能**（README 明确写了不连券商） | **不能**：`execution/trader.py` 被引用了，但仓库里没有这个文件 | 不涉及 |
| 能否接 OKX | 没有 OKX 数据源 | 有 OKX 公共 K 线数据源和下载脚本 | 读本地 parquet |
| 自带的盈利证据 | **没有**。胜率是让模型自己估的，代码里没有任何结果跟踪或盈亏统计 | 作者自测：外汇年化 +3%（Sharpe 0.7–0.9），指数无效，贵金属被作者自己标为 INVALID/SUSPICIOUS；**没有加密货币结果** | 守住概率模型几乎没有预测力（见下文） |
| 方法学质量 | 中：工程量大，但无法回测 | 中偏下：存在多重检验问题 | **三个里最扎实** |
| 规模 | 约 6.9 万行 Python | 约 3.4 万行 | 约 7 千行 |

### 1.1 PA_Agent：重点问题

1. **盈亏比被程序锁死在 1:1**。`trade_metrics.py` 里 `MIN_RISK_REWARD_RATIO = MAX_TP1_RISK_REWARD_RATIO = 1.0`，盈亏比超过 1 时程序会自动外扩止损。同时 prompt 让模型"合理估算胜率（约 45–55%）"。**1:1 盈亏比配 45–55% 的胜率，扣手续费之前就只是接近打平。**（扣费之后见第 3 节。）
2. **"激进 vs 稳"的区别**：v1.3（6.24 版）把"计划型限价 §9.0P"设成了均衡档的默认路径，也就是没有信号 K 也去挂限价单，所以机会更多。但没有任何数据说明多出来的这些单是正期望。
3. **6.16 版留下的本地报告**：38 次分析里给出下单方案 6 次（15.8%），全部是 XAUUSD 15m。只记录了"开单机会"，没有记录这些单最后的结果。
4. **单次调用很重**：阶段一的系统提示约 6 万汉字（市场诊断框架 3.7 万 + 二元决策 2 万 + 人设），阶段二约 3 万字以上，推理强度为 high/max。单次分析要几万 token、耗时分钟级。15m 周期下单品种一天要跑 96 次。这决定了它**只适合 H1 及以上周期、1–3 个品种**。
5. **无法做可信的历史回测**。原因有两个：输出有随机性；模型训练语料可能已经包含历史行情，存在前视偏差。**LLM 策略只能做前向验证，这正好是模拟盘的用武之地。**
6. **⚠️ 我们不能用的部分**：内置的 Trae / Qoder / WorkBuddy / QClaw 连接器会读取这些 IDE 在本机的登录 token，借用它们的模型额度。仓库里还有一份逆向 TRAE 限流的调查文档。这种用法违反这些产品的条款，随时可能失效。我们只走正规付费 API（比如 DeepSeek 官方）。
7. 作者 2026-09-22 的记录：约 771 个测试用例里，48 个失败、28 个报错。

### 1.2 AlphaMaster：重点问题

1. **多重检验 / 数据窥探**：每组每步采样 192 个公式，跑 9000 步，相当于试了约 170 万个公式，再按验证集分数挑最优。验证集既然被用来"挑选"，就已经不算样本外了，而且也没有留出独立的 holdout 测试段。
2. **成本口径偏乐观**：默认单边 0.03%，而且不计资金费率。OKX 普通用户永续合约的费率是挂单 0.02%、吃单 0.05%。
3. **可以复用的部分**：StackVM 公式执行器、特征和算子库、OKX 数据源。它的信号是确定性的，可以先离线回测、再做前向验证，**适合作为 1.0 的规则型策略基线**。

### 1.3 Detect S/R：重点问题

- 做得好的地方：走查回测从结构上防泄漏（检测器拿不到 t 之后的数据）、ZigZag 枢轴按确认时间才放行、有安慰剂（placebo）对照、训练和测试股票池按 md5 互斥。
- 但它是用 **A 股日线**校准的，不是加密货币。
- 实测指标（`data/prob_models.json`，测试池）：
  - 触及概率模型 AUC 0.73–0.78。但"价格会不会碰到这个位"主要由距离决定，本身不构成交易优势。
  - **守住概率模型 AUC 只有 0.59–0.61，Brier skill 只有 0.02–0.025**，几乎等于直接用基础比率（73–77%）去猜。也就是说，"这个位守不守得住"基本预测不了。
- 在 1.0 里的定位：作为止损/止盈的参考位或辅助特征，不单独作为策略。

## 3. 关键数字：手续费门槛

条件：盈亏比 1:1（PA_Agent 的默认）、止损取 1 个 ATR(14)，用最近 12 个月的 ATR 中位数，计算打平所需的胜率：

| 品种 | 周期 | ATR14 | 打平胜率（挂单进 + 吃单出，往返 0.07%） | 打平胜率（全吃单 + 滑点，往返 0.12%） |
|---|---|---|---|---|
| BTC | M5 | 0.14% | 74.6% | 92.2% |
| BTC | M15 | 0.27% | **63.0%** | 72.3% |
| BTC | H1 | 0.60% | 55.8% | 60.0% |
| ETH | M15 | 0.42% | 58.3% | 64.3% |
| ETH | H1 | 0.92% | 53.8% | 56.5% |
| SOL | M15 | 0.48% | 57.3% | 62.5% |
| SOL | H1 | 1.03% | 53.4% | 55.8% |

解读：

- PA_Agent 主打的 15m 周期，打平需要 57–72% 的胜率，而它的 prompt 里预估胜率只有 45–55%。**照原样拿到加密 15m 上跑，大概率是持续亏损。**
- 周期越短，手续费越致命。1.0 应该**优先跑 H1 及以上周期，入场尽量用挂单（maker）**。
- 这张表还没计入资金费率（永续合约每 8 小时结算一次）和 LLM API 的调用费。

## 4. 外部参照：Alpha Arena 第一季

nof1.ai 在 2025-10-18 到 11-03 期间，给 6 个大模型各 1 万美元真钱，让它们交易加密永续合约。结果：Qwen3 Max +22%，DeepSeek +5%，另外 4 个亏了 42–59%（GPT-5 最差，−59%）。只有 17 天、单次运行，**说明 LLM 直接下单的方差极大**，不能作为"LLM 能赚钱"的证据。

## 5. 虚拟钱包怎么做：三种方案

| 方案 | 行情 | 成交 | 优点 | 缺点 |
|---|---|---|---|---|
| **A. 自建本地模拟撮合**（公共 WebSocket + 本地账本） | 真实、实时 | 按规则模拟：挂单按价格穿越成交，吃单加滑点，资金费每 8 小时结算 | 完全可控、可审计；能同时跑 N 个策略；可以故意把成本设得更保守 | 成交模拟偏乐观（忽略排队、部分成交） |
| **B. OKX 官方模拟盘 API**（`x-simulated-trading: 1`） | 真实、实时 | OKX 的模拟撮合 | 下单代码和实盘几乎一样，以后切实盘最省事 | 需要 OKX 账号和模拟盘 API key；不能自定义成本；模拟盘的深度和成交不一定等于实盘 |
| C. 纯历史回测 | 历史数据 | — | 快 | 对 LLM 策略不可信；发现不了实时链路的问题 |

**建议：A 为主**，负责评估策略；**B 为辅**，验证下单链路；C 只用来给 AlphaMaster 这类确定性策略做预筛。

## 6. 1.0 建议架构（只是文字设计）

1. **行情层**：OKX 公共 WebSocket（K 线、标记价格、资金费率、盘口前 5 档）+ REST 补历史；先把 `data/` 补到最新，再补上资金费率。
2. **策略层**：统一接口，输入已收盘 K 线，输出目标仓位或挂单意图。
   - **S0 基线**：买入持有 BTC，加一个"随机入场 + 同样风控"的安慰剂策略。**没有基线，就没法判断是在"刷钱"还是在跟着大盘涨。**
   - S1：AlphaMaster 因子（确定性，可回测）
   - S2：PA_Agent 两阶段 LLM（不要 GUI，只用编排器；限 H1；1–3 个品种）
   - S3：S/R 位叠加到 S1/S2，作为止损/止盈参考
3. **模拟撮合 + 虚拟钱包**：USDT 余额、保证金、杠杆上限、手续费（0.02% / 0.05%，再加 1–2bp 滑点）、资金费、强平价。
4. **风控**：单笔风险 ≤ 1% 净值、单日亏损熔断、最大持仓数。
5. **记录与评估**：订单、成交、资金费全部落库；每个策略出净值曲线、Sharpe、最大回撤、胜率、盈亏比，以及相对 S0 的超额收益；**LLM 调用费也计入成本**。
6. **通知**：沿用两个项目里现成的飞书 webhook。

粗略工作量（单人）：行情 + 撮合 + 钱包 + 记录的 MVP 约 1–2 周；接入 AlphaMaster 2–3 天；PA_Agent 去界面化接入 3–5 天。

## 7. 从 1.0 到 2.0（上真钱）的放行标准

建议现在就把标准定死，避免事后找理由：

- 前向模拟 ≥ 8–12 周，并且 ≥ 100 笔成交
- 扣除全部成本（手续费、滑点、资金费、LLM 调用费）后，跑赢 S0 基线
- 最大回撤低于预设上限（例如 15%）
- 前向结果和回测结果没有显著背离

达不到就不上真钱。**1.0 最可能的结论是"都不赚钱"，这个结论本身就是收益：它省下的是真钱。**

## 8. 其他风险

- **合规**：中国大陆自 2021 年起把虚拟货币相关业务活动定性为非法金融活动，OKX 也不对大陆用户提供服务。模拟盘阶段只读公共行情，影响不大；但 2.0 上真钱之前，需要你自己确认所在地的合规性和账户可用性。
- **数据过时**：本地数据止于 2026-07-10。
- **许可证**：PA_Agent 和 AlphaMaster 都是 AGPL-3.0。如果改了之后作为网络服务对外提供，需要公开源码。

## 9. LLM 在刷钱机里的定位

结论：**主干不依赖 LLM；LLM 作为可插拔、可单独评估的实验臂。**

为什么不让 LLM 直接决定买卖：
- 能赚钱靠的是"别人没有的优势"，不是模型多聪明。同样的 K 线、同样的公开模型，人人都能拿到。
- LLM 没法可信回测：模型可能在训练时见过那段行情（前视偏差），输出也有随机性，只能做前向验证。
- 手续费门槛不随模型变强而降低（第 3 节）。
- 成本和延迟都不小：PA_Agent 一次分析要 5–9 万 token。
- Alpha Arena 的真钱测试显示，LLM 直接交易的结果方差极大。

LLM 适合的角色（按回报排序）：① 写代码、审代码；② 离线提出因子假设，再用锁死的留出数据检验；③ 处理 K 线以外的文本信息（新闻、公告、上下币）；④ 只能踩刹车的否决层；⑤ 运维报告。

在 1.0 里的落地：
- S2 `llm_veto`：规则策略的开仓需要 LLM 批准，LLM 只能否决或减仓（最低到 0.25 倍），平仓永远放行。
- S3 `llm_direct`：LLM 每根 K 线决定方向、止损和止盈。止损被限制在 1–5 ATR，仓位仍由风控层按 1% 风险计算。
- **失败即不交易**：超时、HTTP 错误、拒答、JSON 格式不对、超预算、中转返回的模型与请求不一致，一律不开仓。
- 订单在模型实际答复的时刻才生效，所以模型延迟会如实体现在成交价上。
- 每次调用都落库（提示词、回复、token、延迟），并按**官方价**计费；报告里的 `net_after_llm` 已扣掉这部分。
- Claude 模型走官方 Anthropic SDK（中转需要支持 `/v1/messages`），其他模型走 OpenAI 兼容接口。
- 默认不在历史数据上回测 LLM 策略，需要显式加 `--allow-llm`。
