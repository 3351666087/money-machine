# 刷钱机 2.0：机器学习方案规划（待你审批）

日期：2026-10-08　｜　状态：**草案，你打勾同意之后才动手**　｜　前置：1.0 模拟盘框架（已完成）

## 0. 目标和诚实预期

**目标**：用当前业界和学术界验证过的最强方法，在 OKX 永续合约上找到**扣除全部成本后仍然稳定为正**的收益。先在模拟盘证明，再考虑真钱。

**必须先说清楚的事实**：
- 2026 年 9 月的一篇综述（Zhu & Cai）总结：到目前为止，**没有任何一种 AI 架构被证明能跨市场周期、在考虑容量之后持续赚到净超额收益**。进步主要在预测能力本身，扣成本后的长期净收益证据薄弱。
- 加密货币的机器学习研究里，XGBoost 一类模型确实明显好于线性模型。但超额收益**集中在小币、流动性差、难以成交的币上**，模型越复杂带来的增益也有限。
- 所以本方案的"最可能盈利"不是靠堆最大的模型，而是靠三件事：**选对能赚钱的地方 + 成本感知 + 极严格的防过拟合**。每个阶段都有通过门槛，没过就停，止损成本很低。

## 1. 设计原则（每一条都对应证据或 1.0 的实测结果）

1. **横截面、对冲大盘**：在一篮子币里预测"谁比谁强"，做多强的、做空弱的，对冲掉 BTC 的整体涨跌。这类排序信号在加密货币文献里最稳健（动量、过去超额收益、流动性等因子），也不依赖猜大盘方向。
2. **持有周期按天算，不按小时**：1.0 的实测显示，1 小时周期的策略被成本吃掉了 85–104% 的收益。2.0 每 4 小时到 1 天调一次仓，预测未来 1–3 天。
3. **成本写进目标函数**：Jensen、Kelly、Malamud、Pedersen 的论文（发表于 RFS）证明，不考虑成本的机器学习组合会过度依赖短命的小信号，扣成本后表现差；直接以"扣成本后的净收益"为目标学习仓位，效果明显更好。
4. **只做流动性够的币**：OKX 现在有 485 个 USDT 永续，24 小时成交额超过 5000 万美元的只有 34 个，超过 2000 万的 59 个，其中还混着股票、黄金之类的传统资产合约。宇宙按流动性筛选；小币的"漂亮收益"大多是成本模型骗人。
5. **数据不止 K 线**：再加上资金费率、持仓量、多空比、主动买卖量、永续相对现货的基差。这些是衍生品市场特有的信息，比单纯的 K 线更可能有增量价值。
6. **防过拟合比模型更重要**：锁定一段最终考试数据；所有参数只用滚动的样本外验证来选；记录每一次尝试；用 Deflated Sharpe Ratio 和过拟合概率（PBO）校正"试多了总能碰到一个好看的"。

## 2. 方案总览

```
数据底座（时点正确的币池 + K线 + 资金费 + 持仓量/多空比/主动买卖 + 现货基差 + 每个币的成本模型）
   │
特征工程（约 60–150 个，全部做横截面排名标准化）
   │
模型集成：LightGBM（主力） + TabPFN-3（表格基础模型） + Kronos（金融K线基础模型）
          + 随机特征岭回归 + 基线（动量/趋势）→ 滚动外样本堆叠
   │
成本感知组合构建：直接学"扣成本后的净收益"最优仓位 + 部分调仓 + 波动率目标 + 大盘中性 + 不交易区间
   │
执行：优先挂单（maker），撮合规则沿用 1.0 的保守规则
   │
验证：清洗+隔离的滚动验证 → 门槛A → 锁定数据一次性考试（门槛B）→ 服务器前向模拟 8–12 周（门槛C）
```

## 3. 逐条计划

### 阶段 0：审批与准备
- [ ] **你确认这份方案**（可以逐条删改）
- [ ] 确认算力：先在本机（Apple 芯片）测 LightGBM、Kronos-small、TabPFN 的速度；不够的话决定是租 GPU 还是用 TabPFN 官方的云端 API（只发送行情特征，不含任何个人数据）
- [ ] 确认许可证：Kronos 是 MIT，LightGBM 是 MIT；**TabPFN 新版权重的许可要核实**（研究用通常没问题，上真钱前要再确认）
- [ ] 你先用 `scripts/deploy_server.sh` 把 1.0 部署到服务器（阶段 1 的数据采集要用到它）

### 阶段 1：数据底座（约 3–5 天）
- [ ] **时点正确的币池**：每天按过去 30 天的成交额重新选币，只选加密货币，排除股票、黄金等传统资产合约；把门槛做成参数（候选：日均成交额超过 2000 万或 5000 万美元，约 30–60 个币）
- [ ] **处理已下架的币**（幸存者偏差）：检查 OKX 历史数据下载接口能不能拿到已下架币种的 K 线；拿不到的话，在报告里量化这个偏差可能带来的影响
- [ ] 全部候选币的 1H K 线，从 2020 年起（现有归档有 19 个币，其余用 REST 补）
- [ ] 全部候选币的资金费历史（月度归档 + REST，1.0 已经打通）
- [ ] **持仓量、多空账户比、主动买卖量**：已实测 OKX 公开接口能拿到，但历史深度有限（2023-11 之前的日线持仓量查不到）。要先测清每个指标能回溯多久，决定只用有足够历史的那些
- [ ] **现货 K 线**：用来算永续相对现货的基差和溢价
- [ ] **服务器上马上开始连续采集**：每 5 分钟把全部 USDT 永续的持仓量、多空比、主动买卖量、盘口前 5 档和价差落库。历史接口不够长，越早开始积累越好（这也是你之前说的"连续数据收集"）
- [ ] **按币种的成本模型**：手续费 + 半个价差 + 按成交额占日成交比例计算的冲击成本，参数用实测的盘口快照标定（已实测价差：BTC 0.01bp、SOL 0.86bp、中等币约 2.5bp）
- [ ] 数据质量报告：缺口、异常 K 线、上下架日期、时间戳对齐

### 阶段 2：研究框架与防过拟合（约 2–3 天，先于任何建模）
- [ ] **锁定最终考试数据：2026-04-01 至今**。开发期间任何代码都读不到这段，用代码层面的访问检查来保证
- [ ] 清洗加隔离的滚动验证（López de Prado）：训练集和验证集之间去掉标签重叠的样本，再加一段隔离期，防止信息泄漏
- [ ] 组合式清洗交叉验证（CPCV）：生成多条回测路径，得到收益分布，而不是只有一条曲线
- [ ] **试验登记簿**：每试一次（每种特征组合、模型、参数）都自动记一行；最终结果用 Deflated Sharpe Ratio 按试验次数校正
- [ ] 过拟合概率 PBO（用 CSCV 方法估计），要求低于 0.3
- [ ] 基线（打不过就说明复杂模型没用）：① 多周期趋势组合加波动率目标 ② 横截面动量 ③ 资金费套利 ④ 1.0 的 S0/S1
- [ ] 回测和模拟盘共用 1.0 的引擎（保证一致），按每个币种的成本模型扣成本

### 阶段 3：特征工程（约 3–4 天）
所有特征都只用当时已收盘的数据计算，并在每个时点做横截面排名标准化：
- [ ] **价格和成交量**：多周期收益（1 天、3 天、7 天、14 天、30 天、60 天）、短期反转、过去超额收益（扣掉对 BTC 的贝塔）、波动率和上行/下行波动、偏度峰度、Amihud 非流动性、成交额趋势、距 N 日高低点的距离、Kelly 等人的趋势因子
- [ ] **衍生品**：资金费的水平、变化、累计值；持仓量的变化和"持仓量变化 × 价格变化"的交互；多空比及其变化；主动买卖量的失衡；基差（永续减现货）
- [ ] **市场状态**：BTC 和全市场的趋势、波动率、币之间的相关性、资金费在全市场的分布
- [ ] **Kronos 特征**：用 Kronos（专门在 120 亿条 K 线上预训练的金融 K 线基础模型）的预测收益、预测波动率、不确定性作为特征
- [ ] 特征重要性用"经济重要性"来评估：去掉某个特征后扣成本收益掉多少（JKMP 的做法）；没有增量价值的特征删掉

### 阶段 4：模型（约 5–7 天）
标签是未来 1 天和 3 天收益的横截面排名（扣掉 BTC 贝塔、按波动率缩放），每个时点做排序。
- [ ] **M1 LightGBM**（主力）：排序目标和回归目标都试。加密货币横截面研究里梯度提升树表现最好，多个 Kaggle 金融预测比赛的优胜方案也以它为核心
- [ ] **M2 TabPFN-3**（2026 年 5 月发布的表格基础模型，支持 100 万行、200 个特征）：2.5 版的报告里，默认设置对默认 XGBoost 的胜率在中小数据集上是 100%、在 10 万样本以内的数据集上是 87%；在我们这种信噪比很低的金融数据上是否更好，由滚动验证说了算
- [ ] **M3 Kronos 微调**：在我们的币池 K 线上微调 Kronos-small（2470 万参数）或 Kronos-base（1.02 亿参数）。论文报告在金融价格预测的排序相关系数（RankIC）上比通用时间序列基础模型高 93%。既可以作为 M1 的特征，也可以单独成为一组
- [ ] **M4 随机特征岭回归**（Kelly、Malamud、Zhou《复杂性的优势》）：高维随机特征加强正则化。它是便宜又强的线性家族对照，可以检验"复杂度本身有没有用"
- [ ] **M5 集成**：用滚动外样本的预测做堆叠，权重只用样本外数据估计
- [ ] **元标签**（López de Prado）：再训练一个模型判断"主信号这次可信度多高"，只用来调整仓位大小
- [ ] 每个模型都要和阶段 2 的基线比，并且记进试验登记簿

### 阶段 5：成本感知组合构建（约 3–4 天）
- [ ] 目标仓位 = 预测信号经成本感知优化得到：最大化"预期收益 − 风险惩罚 − 预期交易成本"，每个币的成本用阶段 1 的成本模型
- [ ] **部分调仓**（Gârleanu & Pedersen）：每次只向目标仓位走一部分，并且瞄准"未来的目标"，换手和成本都会大幅下降
- [ ] **直接学习仓位**（JKMP）：以扣成本后的净收益为目标，直接训练仓位函数，和"先预测再优化"的结果对比
- [ ] 风控：对 BTC 的贝塔中性、组合波动率目标（例如年化 15%）、单币仓位上限、总杠杆上限、不交易区间
- [ ] 执行：优先挂单（1.0 的撮合要加"只挂单"订单类型），超时没成交才改成吃单
- [ ] 资金费：组合的预期资金费收支计入目标函数（做空资金费高的币还能顺带收资金费）

### 阶段 6：门槛 A（开发期的滚动验证，扣除全部成本）
**全部满足才进入下一阶段，否则停下来复盘，不硬凑：**
- [ ] 扣成本后年化 Sharpe ≥ 1.0，并且比最好的基线高至少 0.3
- [ ] Deflated Sharpe Ratio 显著（按试验次数校正后，真实 Sharpe 大于 0 的概率 ≥ 95%）
- [ ] PBO < 0.3
- [ ] 至少 70% 的季度是正收益，最大回撤 ≤ 20%
- [ ] 成本翻倍后 Sharpe 仍然 ≥ 0.5
- [ ] 收益不是只靠一两个币或某一个月贡献的（按币、按月拆开看）
- [ ] 对 BTC 涨跌的暴露确实接近 0

### 阶段 7：引擎改造（约 3–5 天，可以和阶段 3–5 并行）
- [ ] 支持"组合型策略"：同一个决策时点同时看到所有币，输出各币的目标权重（1.0 是逐币决策）
- [ ] 订单类型增加"只挂单"，成本按币种模型计算
- [ ] 模型版本管理：每个模型文件带训练数据区间、特征列表、哈希值，模拟盘只加载登记过的版本
- [ ] 定期重训：每周或每月在服务器上滚动重训（只用已经发生的数据），新模型先在影子模式里跑一周再替换
- [ ] 监控：特征分布漂移、预测和实际排序的相关性（IC）滚动值、成交率、实际成本和模型预估成本的差距，异常时发飞书提醒

### 阶段 8：门槛 B（锁定数据一次性考试）
- [ ] 把最终配置冻结（写下哈希值），在 2026-04-01 至今的锁定数据上**只跑一次**
- [ ] 通过标准：扣成本后 Sharpe ≥ 0.5，并且不低于开发期的一半；最大回撤 ≤ 20%
- [ ] **没通过就停**，不准改了参数再考一次，否则这段数据就不再是"考试"

### 阶段 9：门槛 C（服务器前向模拟盘 8–12 周）
- [ ] 部署成模拟盘里的新一组（和 1.0 的 S0/S1 并排跑，同样的钱包规则）
- [ ] 前向结果要落在回测收益分布的合理范围内（用自助法估计的 95% 区间）
- [ ] 通过 1.0 预先定好的放行标准：至少 56 天、至少 100 笔、扣全部成本后跑赢基准和安慰剂、回撤 ≤ 15%
- [ ] 全部通过后，再单独写一份上真钱的方案（小资金、OKX 子账户、硬止损），由你来决定

## 4. 明确不做的事，以及原因

- **端到端强化学习交易**：学术论文很多，但样本外扣成本后的证据很弱，也最容易过拟合
- **高频和做市**：没有逐笔和盘口的历史数据，网络延迟也比不过专业机构
- **小币和刚上线的新币**：论文里的超额收益大多来自这里，但实际成交不了、成本模型也不可信
- **LLM 直接下单**：1.0 已经讨论过，LLM 只作为可选的实验组
- **用锁定数据调参**：一旦用它调参，整个验证就失效了

## 5. 风险
- **最可能的结果**：门槛 A 或 B 没过，结论是"在流动性好的币上找不到稳定的净超额收益"。这仍然是有价值的结论，因为它省下了真钱。
- **数据**：持仓量等衍生品指标的历史较短，可能只够 1–2 年训练；服务器上的前向采集可以弥补，但需要时间积累。
- **市场变化**：2024–2026 年的市场结构不一定会延续，所以需要定期重训，并在模拟盘里持续监控。
- **算力**：TabPFN 和 Kronos 在数据量大时需要 GPU，可能要租用（几十美元量级），或者只在子样本上用。
